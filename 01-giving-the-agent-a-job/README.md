# 01: Giving the agent a job

Files for part one of my series, Guide for building an autonomous agentic system administrator: [Part 1: Giving the agent a job](https://onet.com.au/blog/sysadmin-agent-guide-part-1/).

| File | Use it when |
|---|---|
| `hermes-self-modification.md` | **Before anything else.** Decide how your agent may change its own skills, memory and identity file. |
| `brief-template.md` | Giving the agent its first real job: a daily health check, and the questions to answer before it runs. |
| `soul-template.md` | Writing the agent's identity file with the agent. |
| `mandate-template.md` | Defining what the agent is responsible for, what it may decide alone, and what it must bring to you first. |

These are working documents from a real setup, generalised for public use. They have not been tested in this generic form. They are starting points: customise them with your own agent, for your own estate.

**Version.** Checked against Hermes Agent upstream commit `e1fdf003` (5 October 2026). Hermes has thousands of commits per month, so ask your agent to check anything Hermes-specific against your installed version.

> **About the name.** Maxi Calder is my sysadmin agent. Its full name, Maxine Verity Calder, was chosen by the agent itself using an agent naming convention skill. In its own words: "Maxine is the human working identity I keep behind Maxi. Verity encodes my truth-seeking. Calder encodes my habit of forging ideas under heat." This was an experiment in anchoring agents to their role and mitigating alignment drift. There is no definitive evidence this works, other than agents always voting to keep their identity when asked, and the user (me) having a better user experience. (Steve Waddington)
