# 05: Reflection that changes work

Files for part five of Guide for building an autonomous agentic system administrator: [Part 5: Reflection that changes work](https://onet.com.au/blog/sysadmin-agent-guide-part-5/).

| File | Use it when |
|---|---|
| `improvement-research.md` | Commissioning bounded research: focus, source budget, stop conditions, report contract, write boundaries and a real handoff for review. |
| `reflection-store.md` | Keeping specific lessons available to the next run, with example JSON, source references, reinforcement, review and the limits of the expiry rule. |
| `reviewing-improvements.md` | Reviewing proposals one at a time and testing an accepted change before keeping it. Includes a trial card, no-signal outcomes and a monthly process review. |

These are generalised rewrites of our estate-authored process, not upstream Hermes skills. They have not been run-tested in this generic form. Customise them with your own agent and operator, choose actual paths and review routes, then run a local manual trial before considering scheduling or publication. No active skill installation or expanded authority is supplied by these files.

The source process researches the agent's development, not daily AI news. Report writing, human review, implementation and verification are separate steps. The files keep that separation deliberately.

**Version:** Process inspected on 21 October 2026, running Hermes Agent upstream commit `e1fdf003` (5 October 2026). Hermes has thousands of commits per month, so ask your agent to check anything Hermes-specific against your installed version.
